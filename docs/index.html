A standalone Python coding agent

The work stays in the log.

CadeMini runs coding tasks in your workspace, then appends every task, model step, tool call, result, and recovery decision to one durable session record. Resume, rewind, or audit the run without reconstructing what happened.

The invariant

History is rebuilt, not remembered.

CadeMini does not depend on a hidden chat loop to reconstruct what it did. Durable facts go into the log first; model-visible context is derived from that record.

“The session log is the source of truth. The model-visible history is a deterministic projection. Request construction only produces the current request.”
01

Append the fact

User input, model output, tool results, and compaction decisions are written before the next step can rely on them.

task · assistant · tool_result · summary
02

Project the view

The active branch becomes model-visible history. Compaction and window changes are facts in the log, never rewrites of it.

active branch → model context
03

Build the request

Only the current request is assembled, with instructions, skills, memory, a goal, and the projected history.

projection + current inputs

If the model can see it, the session log can explain where it came from.

Built for long work

Stay oriented after the first hundred steps.

A compact runtime is useful only when the surrounding work remains inspectable. These capabilities share one session log, one policy layer, and one execution loop.

Continuity

Resume the branch, not a vague summary.

Continue the latest session, select an older one, navigate the full history tree, or fork a branch into a new session. Positions survive restarts.

--continue--resume/tree/fork/clone

Context

Compact without pretending the past vanished.

Compaction appends a summary fact and keeps a recent tail. The original entries remain available, and a window reset can use NOTE.md as a handoff.

/compact/rollover/contexthistory

Recovery

Undo the effect, keep the account.

File snapshots and session checkpoints support undo, redo, rewind, and selected-file revert. Recovery restores tracked files without erasing the evidence of the turn.

/undo/redo/rewind/revertcade --undo

Execution

Tools pass through a policy, not a vibe.

Read, write, edit, shell, Python orchestration, web retrieval, MCP, and delegation are typed tool calls. Modes, rules, grants, and OS confinement decide what runs.

planaskbuildrulesbwrapSeatbelt

Extensions

Extend the edges, not the core.

Skills add on-demand instructions. Memory keeps durable preferences. MCP adds external tools. Subagents run in separate child sessions with their own logs.

Two terminal shapes, one runtime.

Use the inline TUI for steering, approvals, and branching, or run one task with -p and JSONL events. Both paths share the same session and tools.

One request at a time. Every step accounted for.

Safety and control

Autonomy with an audit trail.

The default build mode is useful, not unrestricted. Every call still passes through mode policy, rules, approvals, and the available OS sandbox.

Approval can answer an ask. It cannot override an explicit deny.

Execution policy by mode
Surface plan ask build
Inspect files Allow Allow Allow
Change files Deny Ask Allow
Normal dev shell Read only Allow Allow
Destructive shell Deny Ask Ask
MCP tools Deny Ask Ask
OS confinement where available

Linux uses bubblewrap; macOS uses Seatbelt. Windows keeps application policy and approvals but skips OS-level confinement.

Protected paths stay protected

Explicit access to .env* and common credential paths requires approval on every use. Grants cannot bypass a deny.

Scoped writes by default

workspace-write keeps writes in the project and private session temp. External writes request extra permission.

Recovery is deliberate

Rewind, undo, and revert validate affected files before modifying them. Conflicting later edits block automatic restoration.

Extensions

Power at the edges, not a second runtime.

Skills, memory, MCP servers, and subagents attach to the same loop. They add context or tools without creating a parallel source of truth.

Skills

Instructions on demand

Load a SKILL.md only when a task needs it. Reference files are read selectively, and scripts still pass through ordinary shell policy.

Memory

Facts that outlive the task

MEMORY.md holds durable preferences and conventions. It enters request context without becoming another conversation message.

MCP

External tools, explicit names

Connect stdio or Streamable HTTP servers. Their tools appear as mcp__server__tool and ask by default unless a rule allows them.

Subagents

Separate sessions, inherited limits

Delegate focused work to child sessions with their own logs. Children cannot expand parent permissions or recursively delegate.

The core stays small because every extension enters through an explicit seam.

Before you run it

Questions worth asking.

The important behavior is in the record, the policy, and the recovery path — not in a promise about model memory.

Where does session state live?

Session logs are JSONL files under .cade/sessions. Snapshots and recovery data live under .cade/snapshots and .cade/recovery. Project configuration is cade.json.

Does compaction delete the original history?

No. Compaction appends a summary fact and keeps a recent tail in the projection. Original entries stay in the session log and remain available through the history tool.

Is every platform sandboxed the same way?

No. Linux uses bubblewrap and macOS uses Seatbelt. Windows skips OS confinement and relies on application policy, approvals, and the configured workspace scope.

Can I use an API key instead of ChatGPT login?

Yes. Use cade login --provider openai or cade login --provider deepseek. Cade supports the Responses protocol through all three routes.

Can this read the earlier Cade project's state?

No. CadeMini is a standalone distribution with its own credential, session, and configuration formats. Start with clean ~/.cade/ and workspace .cade/ directories.
