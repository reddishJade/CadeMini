# 快照与目标

## 文件快照

文件工具修改文件之前，Cade 会记录快照。快照存放在 `.cade/snapshots` 下，包含一个 JSONL 索引，每个快照一个目录。捕获操作追加并同步一条索引记录。残缺的最后一行会被忽略，下次捕获前修复；完整记录损坏时会阻止捕获。参见[决策 0014](../decisions/0014-storage-append-cost.md)。

覆盖的变更：

- `write` 和 `edit`。
- 简单的字面文件 shell 修改：`rm`、文件到文件的 `mv`/`cp`、`touch`、`echo` 重定向和 `sed -i`。带引号的文件名可以含空格。目录操作数、展开和未知命令形式不会被捕获。
- 创建文件时会记录“原本不存在”；撤销会删除该文件。

不覆盖：

- 复杂流水线、命令列表、未知脚本，以及不写明文件名却修改文件的命令。
- 超过快照上限（5 MiB）的文件会被拒绝，不会静默跳过。
- 不复制目录树；目录修改会被跳过。

## 撤销

```bash
cade --undo
```

这个命令与 TUI `/undo` 共用检查点恢复协议。它撤销最新会话的一次操作，包括对话位置和已跟踪的文件变更。用 `cade --resume ID --undo` 指定会话，再在 TUI 中恢复该会话即可用 `/redo` 重做。命令不联系 provider，也不启动 MCP。参见[决策 0013](../decisions/0013-unified-cli-undo.md)。

恢复会先校验所有受影响文件，再开始写入。冲突、损坏的载荷和未知结果都会阻止恢复。执行恢复之前，先停止外部文件写入者。没有自有检查点的独立文件快照不会产生可撤销操作。

快照是项目状态，不是会话事实。它们不属于 JSONL 会话分支。

## 检查点恢复

每轮根用户输入在执行前创建检查点。已登记的文件修改会保留修改前后内容、存在性和权限。同步子代理共享父级的捕获范围。排队输入在执行开始时获得检查点；引导仍属于当前回合。

- `/undo` 撤销一轮或一次显式恢复操作；`/redo` 重新应用一次。两者都不重跑工具，也不联系 provider。历史在重启后保留。
- `/rewind` 选择活动路径上的一条用户提示，再选择对话、代码或两者，随后显示预览并确认。它恢复到该提示之前的位置。
- `/revert` 选择一段轮次和一个或全部已跟踪文件。显式路径参数可以选择多个文件。对话保持不变。

新操作会丢弃当前重做链。旧对话分支仍然保留。树导航从不恢复文件；过期的撤销/重做不能跨过已变化的对话位置。Rewind 仍可使用自有检查点，并根据实际操作计算代码变更，包括期间发生的撤销、重做和 revert。复制的会话不继承工作区操作。没有自有检查点的历史提示只支持恢复对话。

恢复在修改文件之前检查所有选中的文件和内容块。目标已变化、结果未知、内容块损坏、符号链接、硬链接或受保护的元数据路径都会阻止自动代码恢复。如果后续编辑冲突，恢复较旧的区间也会失败；没有自动反向补丁合并。文件上限对两份镜像都生效。事后镜像缺失时，该回合的代码检查点会被标记为不完整，不会假装恢复可用。未选中的文件和用户的 Git 索引保持不变。目录树、未跟踪的 shell 变更和外部副作用不会恢复。

协作操作共用 `.cade/recovery/workspace.lock`。操作日志和检查点链接使用该目录下的封闭记录。`pending.json` 计划在恢复开始前保存两份镜像。文件按单个文件原子替换；多文件恢复不是整个文件系统层面的原子操作。中断后，恢复指定的会话即可幂等完成计划。如果出现第三个外部编辑过的状态，恢复会停止，不覆盖该编辑。解决报告的冲突后继续；不要删除待处理计划来绕过写入保护。在计划完成前，代理的新写入会一直被阻止。外部编辑器不遵守这把锁，恢复期间必须停止它们。只读模式会阻止代码恢复；仅恢复对话仍然可用。Esc 取消预览，不取消正在提交的文件恢复。正常退出 TUI 会等待恢复提交完成；进程被强制中断时使用待处理计划。

只恢复代码时，模型可见的对话消息保持不变。下一次请求会收到一条有审计记录的通知，要求检查已恢复的文件，而不是相信旧工具的效果。设置、凭据、授权和外部服务不会随对话历史回退。

## 目标

目标保存在 `.cade/goal.json` 中，包含目标内容、状态（`active`、`done`、`paused` 或 `blocked`）、更新时间和可选的阻塞原因。修改使用 `.cade/goal.lock`；完成和阻塞操作校验 `goal get` 返回的版本，避免旧模型请求修改后来更新的目标。

```bash
cade --goal "Implement the backend and verify every requirement" --max-steps 100 "Start the task."
```

TUI 命令：

- `/goal` 显示目标、阻塞原因和自动续跑授权状态。
- `/goal TEXT` 设置目标并授权续跑。
- `/goal pause` 保存暂停状态，并取消当前工作。
- `/goal resume` 为未完成目标重新授权；TUI 空闲后开始执行。
- `/goal done` 标记完成；`/goal clear` 删除目标。

应用与模型工具共用同一个目标存储。模型正常结束一轮后，已授权的活动目标继续使用现有循环执行。排队的人工输入优先。同一次运行的自动轮次共用 `--max-steps` 和用量统计，最终回复不会重置额度。取消、错误、输出截断或步数耗尽都会撤销续跑授权。只读和 Plan 会话不自动续跑，因为策略禁止它们调用完成工具。

授权只在当前进程中有效，并绑定目标版本。加载已有目标或切换会话历史不会自动授权工作，须使用 `/goal resume`。恢复后的运行获得新的步数额度。目标没有跨运行持久保存的 Token、时间或费用预算。

自动输入使用 `user` 事件记录，`source` 为 `goal`。这些输入在同一会话中保持目标，但不会出现在人工提示选择器中。换窗保留原任务和 steering，不把每次自动提醒都复制到交接。活动目标仍属于请求上下文。

提示要求模型在完成前，逐项用当前产物和工具结果验证要求。`goal complete` 和 `goal block` 必须提供 `get` 返回的 `updated_at`，`block` 还必须提供具体的 `reason`。自动目标轮次不能设置、清除、暂停或恢复目标。这些检查控制操作权限和版本，不是独立验收器；完成证据是否充分、同一阻塞是否持续三轮，仍由模型判断。共用步数上限限制无进展续跑。

工作细节用 `NOTE.md`，长期项目事实用 `MEMORY.md`。
